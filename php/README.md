# Kurage AfterCare Navi（kacnavi）

**身内が亡くなったあと、何を、いつまでに。** 故人の状況をえらぶと、当てはまる手続きだけが期限の順に残ります。
期限は e-Gov法令検索の条文まで降りて確かめたものだけを載せています。

- デモ: https://kurage.exbridge.jp/kacnavi.php/
- 手続き 48件 ／ 条件 37項目 ／ 市区町村ページ 1,912枚
- PHP 1ファイル＋SQLite 1本。**入力された故人の情報は、どこにも送りません。**

## なぜ作ったか

死亡後の手続きを並べたページは無数にあります。ほとんどが同じことを書いていて、
**どれが自分に要るのか分からない**のと、**根拠がどこにも書かれていない**のが困りどころです。

このシステムは2つだけ違うことをします。

1. **要らないものを消す。** 48件を全部やる人はいません。世帯主だったか、持ち家があったか、
   山林はあるか。状況をえらぶと、当てはまらないものが消えます。
2. **期限に条文を付ける。** 期限は改正で動きます。相続登記の3年は2024年4月1日施行で、
   それ以前は義務ですらありませんでした。条文を持っていなければ古い解説を写すだけになります。

条文まで降りたので、よく見る書き方との食い違いが見つかりました（詳しくは docs/DATA.md）。

- 死亡届の起算日は「亡くなった日」ではなく「**死亡の事実を知った日**」（戸籍法86条1項）。
- マイナンバーが年金に登録されていれば、年金受給権者死亡届は**出さなくてよい**（厚生年金保険法98条4項ただし書）。
- 世帯主変更届は、残る世帯員が1人だけなら**要りません**。
- 農地の届出は「**遅滞なく**」（農地法3条の3）。10か月は相続税の期限で、別の話です。
- 山林を相続したら**90日以内**に市町村へ届出（森林法10条の7の2・同施行規則7条1項）。相続登記の3年とは別。

## 画面

| パス | 内容 |
|---|---|
| `/` | 死亡後の手続き一覧表（48件・期限順）。状況をえらぶと当てはまるものだけに |
| `/when/<g0〜g4>` | 時期ごと（7日以内／14日以内／3〜4か月／10か月〜3年／期限なし） |
| `/p/<手続きid>` | 期限・窓口・持ち物・**根拠の条文そのもの**・e-Gov へのリンク |
| `/city/<都道府県>/<市区町村>` | その市区町村の窓口でする手続き＋その地域で1年間に何人が亡くなっているか |
| `/pref/<都道府県>` | 市区町村の一覧（死亡者数・人口・全国順位つき） |
| `/api/check?c=…` | JSON。条件の並びを渡すと該当手続きと条文の引用が返る |
| `/sitemap.xml`, `/llms.txt` | SEO・AEO |

## データ

| データ | 出所 | ライセンス |
|---|---|---|
| 法令の条文 | e-Gov法令検索 法令API v2（デジタル庁） | 政府標準利用規約(第2.0版) |
| 市区町村 1,912件 | 総務省 全国地方公共団体コード | 同上 |
| 人口・世帯数・年間死亡者数 | 総務省 住民基本台帳に基づく人口、人口動態及び世帯数 | 同上 |

市区町村の公式ページの本文は**転載していません**。葬祭費の金額や受付時間は条例と運用で決まるので、
このシステムは出しません。

## 作り直し方

```bash
/usr/bin/python3 scripts/fetch_law.py      # 条文を取る（24法令）
/usr/bin/python3 scripts/fetch_cities.py   # 市区町村（総務省）
/usr/bin/python3 scripts/fetch_stats.py    # 人口・死亡者数（総務省）
/usr/bin/python3 scripts/verify_law.py     # 条文の引用を1件ずつ検算（落ちたら公開しない）
/usr/bin/python3 scripts/build_db.py       # SQLite を作る
/usr/bin/python3 scripts/selftest.py       # 画面を実際に叩いて中身を見る（15件）
/usr/bin/python3 scripts/shot.py           # 320/360/390/430px の横はみ出しを実測
/usr/bin/python3 scripts/deploy.py         # heteml へ（FTPは1接続にまとめる）
```

**`verify_law.py` を通さずに公開しない。** 条文の引用が実在するか、書いた日数が条文本文に
出てくるかを34件ぶん突き合わせます。改正で条文が動けばここで落ちます。

## 手続きデータの直し方

`data/procedures.json` の1件はこの形です。事務所の人が自分で足せます。

```json
{
 "id": "shibo-todoke", "name": "死亡届", "group": "g0",
 "deadline": {"kind": "期限", "n": 7, "unit": "日",
              "from": "死亡の事実を知った日", "short": "7日以内",
              "text": "知った日から7日以内（国外で亡くなったときは3か月以内）"},
 "law": [{"name": "戸籍法", "article": "86", "expect": "七日"}],
 "where_kind": "city", "where": "…", "who": "…", "why": "…（**太字**が使えます）",
 "need": ["setainushi", "nokoru2"], "need_any": [], "unneeded_if": ["mynumber_nenkin"],
 "docs": ["…"], "fee": "無料"
}
```

- `need` は全部満たすとき、`need_any` はどれか1つ満たすときに出ます。どちらも空なら誰にでも出ます。
- `unneeded_if` に当たるときは**消さずに**「出さなくてよい場合があります」と印を付けます。消すと不安になるからです。
- `law` の `expect` に条文の語（`七日`）を書いておくと、`verify_law.py` が本文にあるか確かめます。

## 自分のところに置く

PHP が動くサーバーに `php/kacnavi.php` と `php/kacnavi_data/` を置くだけです。
heteml では階層の `.htaccess` に `AddHandler php-script .php` が要ります（既定は PHP 5.6）。

市区町村・議員事務所・士業の事務所が、自分の地域の葬祭費の金額や窓口の課名を足して使えます。
